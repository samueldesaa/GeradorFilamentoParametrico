## App and design direction

This is a Portuguese-language parametric filament generator for 3D printing. It uses Vite, vanilla JavaScript, CSS, and Three.js. Preserve this stack unless the user explicitly requests otherwise.

The user likes green but rejects generic AI aesthetics and overdesign. Do not invent a product name, brand, promotional labels, dramatic headline, or unnecessary copy. Use “Gerador paramétrico para impressão 3D” as the functional page title. Keep text large and high-contrast, content compact, and units consistent (requested meters remain meters). Show filament diameter with the related inputs; remove unnecessary metrics such as path point counts and redundant warnings. The primary action is “Pré-visualizar” (explicitly previews 3D, not export), then becomes “Exportar STL”. The 3D preview replaces the 2D view in the same space; provide a clear way back to parameters and 2D. Add visible light/dark controls, a user-activated high-contrast toggle, and font-size increase/decrease. Normal borders should be subtle; increase vertical spacing between fields. Use a larger rounded/handwritten title font if appropriate (maximum three font families). Keep the project-specific square grid geometric and correctly aligned; do not use vague decorative backgrounds. Apply the full checklist in Obsidian `Skills/frontend/minhas-preferencias.md` and `ClaudeBrain/Memoria/preferencias-design-anti-ai-slop.md` before UI edits; validate each requirement after.

The product is a Portuguese-language parametric filament generator using Vite, vanilla JavaScript, CSS, and Three.js. Preserve this stack unless asked otherwise. Make every app/site responsive. Rounded corners should be intelligent: consistent and purposeful for grouping or touch, never arbitrarily pill-shaped. Font mixing (maximum three families) should suit the product. Keep copy concise. Before implementing frontend in a new project, first create a `testes-front/` folder with separate responsive HTML comparison pages containing three options per relevant decision axis (typography, palette, hierarchy, layout/spacing, corners, controls/footer); show them to the user and wait for approval before applying a visual direction. For this project specifically, use a geometrically square background grid, retain the three shape icons, draw ruler-style width and height measurements along separate sides of the dashed bed, keep parameter controls visible while 3D renders as a contained inset over the same square preview viewport, and show the author's credit and provided contact links in the footer. Approved design direction for this project: corners C (organic, about 20px, pill actions), palette A green leaf (#121a14 background, #202a21 surface, #f1f4ec text, #b8ef63 accent), hierarchy C (dominant title), layout B (airy), typography B (Manrope UI, Roboto Mono numbers, Momo Signature title). Footer/controls A; footer uses three vertically stacked contact items, each with icon, full identifier and action: full email + “Enviar email”, full GitHub handle and Instagram handle + access links. Do not reopen these choices without user request; do not generalize them to other projects. The footer should be a softly bordered block aligned to workspace width; stack on narrow screens. Keep preview actions in the form's action area, where “Pré-visualizar” lives; do not move Back/Export to the preview header. Use exactly two ruler labels: width horizontally above the dashed bed and depth vertically beside it, with aligned ticks. Keep the default first screen feeling complete without clipping, with compact but legible overall scale and generous field spacing. Give shape buttons comfortable padding. If any input changes while in 3D preview, return automatically to 2D. Do not generalize this project's background grid to other sites. Consult Obsidian `Skills/frontend/minhas-preferencias.md` before UI work.
